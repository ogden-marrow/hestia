# Changelog

All notable changes. Dates are 2026-11-11 unless noted. This project has not cut a release yet; everything is under Unreleased.

## Unreleased

### Removed
- **The standalone launcher window** (`hestia --launch`, its toggle and sizing): the Shell extension owns Alt+Space. Search inside the app and `hestia --serve` (the engine behind the Shell bar) are unchanged; the desktop entry's "Search…" action opens the app's Search screen.

### Added
- **Questions in the Stream** (engine, #254): Hestia now keeps an append-only answers log, `<stream>/answers.jsonl`. The nightly `lifestream suggest` writes an `asked` line for each folder that is new to the question queue (or whose files changed), and every answer writes an `answered` line from the one place answers are recorded (`teach`): when, who (`you` or `model`), the folder relative to your home, the label picked and, if the answer moved files, the undo batch. Only folders and labels, never file names or contents. `lifestream feed` shows them as `question_asked` ("Hestia has 3 questions about Downloads") and `question_answered` ("You answered: Taxes for Downloads/2024", with Undo when it moved files). New for the app: `teach_and_file` records an answer and files what it covers in one undoable batch. The Questions screen switching to it is a separate change.
- **Moving several things at once is one Undo** (engine, #231): `lifestream folder move-many --to DEST PATH...` (and `tree::move_many` for the app) moves files and folders together as ONE undo batch, so one Undo puts them all back. Every item is checked first with the same refusals as moving one file or folder (never overwrite, no symlinks, nothing hidden, outside your home folder or sensitive, not into itself, same disk only); if one is refused, nothing moves and the message names it. If the disk changes midway, what already moved goes back and nothing is recorded. The feed shows it as one item: "Moved 3 items into Archive". The Folders screen switches to it separately.
- **Left out and why** (engine, #227): `lifestream left-out [--limit N]` lists what the backup does NOT hold, one JSON object per line, newest first, then a summary of counts: files too large, unreadable, private by Hestia's never-capture list, secret-looking lines left out of a file, files withheld whole for a possible secret, and links not followed (outside the home folder or to a private file), each with a plain sentence ("120 MB is over the 50 MB limit", "2 lines that looked like secrets were left out"), when it was first left out, and whether a fix by you can bring it in. `lifestream backup-state` now carries the counts as `left_out`. The capture and the watcher record these in `skipped.jsonl` and `withheld.jsonl` in Hestia's data folder on this computer (reason, path and numbers only, never the secret or the line); refused paths, which were only on the watcher's error output before, are now listed too. There is no "back this up anyway" yet. The Computer > Backup screen is a separate change.
- **Update Hestia without a terminal** (engine, #265): `lifestream update check` says in one JSON line whether a newer Hestia is on the public repository and what changed (up to ten plain lines from this changelog), `lifestream update apply` updates with progress events and `lifestream update rollback` goes back to the build before. Installs from a git checkout fetch the public repository over https, with no credentials and a 20-second limit, and only fast-forward the checkout. An update waits for a running backup or restore check, refuses a checkout with changes of its own, and switches only after the new build starts; the previous build is kept for rollback. Every install now puts each build in its own folder under `~/.local/lib/hestia/builds/` with the programs as links, and records what it installed in `~/.local/share/hestia/install.json`. A user timer is now restarted only when its unit file changed. Updates for downloaded releases come with signed releases (#244). The Settings > About screen is a separate change.
- **"Only on this computer" is no longer "backed up"** (#256): `lifestream backup-state` now also looks at the home repository itself, offline. With no push target that Hestia has verified private (never signed in, the remote removed, or a remote nobody checked) it says `local_only`: "Your backup is only on this computer. Sign in to keep a private copy online." A new computer gets 24 hours from its first commit before this counts, then one notification per episode like any failure. With a verified private copy, a commit that has not reached it for over a day is `failing`: "Your newest changes have not reached your private copy for over a day." The tray treats `local_only` as needing you. The watcher now records the last definite answer of its private check in `private-check.json` (repository name and yes/no only).
- **A weekly restore rehearsal** (#226): a backup nobody has restored is a hope. Once a week (`hestia-rehearse.timer`: weekly, catches up after the computer was off, randomized, idle priority, skipped on battery) Hestia copies the home repository's latest commit into a private scratch folder and restores it into a fake home there, first as a dry run and then for real, then checks that the manifest and capture list parse, every restored file has the repository's content and a safe mode (no setuid, no group or other write), nothing that runs by itself and no key or keyring was written, no link was followed, nothing outside the scratch folder changed (your real home's key and startup files are checked before and after) and the secret scanner finds nothing. The result is `rehearsal.json` next to `watch.json`: `passed` or `failed` with plain sentences (no paths, no contents). `lifestream backup-state` now carries `rehearsal` (`at`, `result`, `age_days`) so the app can say "Last restore check: passed 3 days ago"; a failed or two-week-old check is only a second line of the reason of a backup that already needs you. Run it by hand with `rehearse.sh` (installed beside `watch.sh`); exit 0 passed, 1 failed. Packages and desktop settings are not rehearsed. The restore itself now sets `umask 022`, so a person whose umask is 002 no longer gets group-writable folders from it, and its file and folder rules moved to one shared file (`restore-rules.sh`) that the rehearsal checks against.
- **A notice when the backup keeps failing** (#225): a person who never opens Hestia now finds out. `lifestream backup-state` is the one policy (ok, failing, stale after 36 hours without a success, or unknown, with a plain sentence); once a problem has lasted 6 hours the watcher sends ONE desktop notification ("Hestia: your backup needs you", no paths, no secrets), never again for the same problem, and one quiet "working again" only if a failure was told. `notifications=off` in the settings file turns it off. The tray icon turns warm orange with the reason in its tooltip and menu. A stopped timer shows in the tray and the app but cannot send a notice itself.
- **The Stream's feed** (engine): `lifestream feed [--since 2h|TIMESTAMP] [--limit N]` prints what happened and who decided it, newest first, one JSON object per line: filed, moved, renamed, folder created, undone, backup saved and backup failed, each with the actor (a Hestia rule, the models, you or the watcher), a one-sentence reason, a plain summary, a count, up to five paths relative to your home, and the batch id that `lifestream file --undo --batch ID` takes back. The move journal now records the actor and reason for every batch, undo keeps a log of what it put back, and the watcher keeps its last 200 runs in `watch-history.jsonl`. Read-only, and any line it cannot trust is skipped. Questions and scans are not logged yet, so they are not in the feed. See `lifestream/README.md` for the contract.
- **Undoable folder moves and new folders** (engine): `lifestream folder move FROM TO` renames a folder (same disk only, never merges or overwrites,
  refuses symlinks anywhere on the path, hidden or sensitive places and moving a folder into itself) and `lifestream folder new PATH` makes one empty
  folder. Both are written to the undo journal; `lifestream file --undo` renames a folder back (never overwriting) and removes a new folder only
  while it is still empty, otherwise it says it kept it.
- **Folders** (Explore): a real tree of your home folder. Expand and collapse, breadcrumbs, select; rename or move a file with Undo, through the same journaled mover as filing. Nothing is ever deleted. Moving whole folders waits for an engine API.
- **Applications** (Explore): every installed app and game in one list with its icon: desktop entries (native, Flatpak, Snap, your own), Steam shortcuts and installed Steam games from Steam's own manifests. Search, All / Games / Apps, group by kind or source, sort by name or most used; click to open.
- **A calm backup status**: the header says "Backed up 12 minutes ago" on every screen; when it is not true, Today shows "Your backup needs you" with one plain action (back up now, or sign in).
- **Undo for filing** (engine): every batch of moves is written down; `lifestream file --undo` puts the last batch back, one file at
  a time, never overwriting, never leaving your home folder, and leaves what it could not restore to be retried.
- **Sign in with GitHub** (engine and screens): device-flow sign-in, find, adopt or create your private home repository.
  The token lives only in the system keyring and is refused if there is none. Needs the project's GitHub Client ID to go live.
- **Machine watcher shipped with Hestia**: captures packages, snaps, flatpaks, config, dotfiles and desktop settings every
  few minutes when the computer is quiet, one commit per kind of change, and pushes to your private repository.
- **Safe restore** (`bootstrap.sh`): a dry run by default; copies instead of linking, never overwrites, and holds back
  anything that runs by itself until you ask.
- **Design system and redesigned Welcome, Today, sidebar and wording**; the launcher shows why an app did not open.
- **Release packaging**: one script builds the tarball and `.deb` with checksums and a signed build attestation.
- **CI**: the whole workspace is lint-clean (clippy with warnings as errors) and so are the shell scripts (shellcheck), clean-computer end-to-end test, release rehearsal, dependency-source check, privacy check, uninstall test.

### Fixed
- **A stopped or dead watcher timer now raises its one notification** (#252): only the watcher used to send the notice, so a disabled `hestia-watch.timer` showed `stale` in the tray and the app but told nobody. The engine now owns deciding, sending and remembering (`lifestream backup-state --notify`, one wording, one `notify-send`), and the tray, which runs for the whole session, calls the same code every minute (and once at start, before it looks for a tray host). A lock on `notified.lock` makes decide-send-remember one at a time, so the tray and the watcher never both tell one problem. `notifications=off` is honoured. `--mark-notified` and its exit code 10 are gone: `--notify` replaces them.
- **A failed commit no longer blocks the backup after its cause is fixed** (#253): a commit that failed (no git name or email, a commit that could not be signed) left its files staged, so the next run skipped the first capture and kept saying "N change(s) could not be committed". Every watcher run now starts by unstaging the capture folder (the index only; your files are never touched), so the run after the fix commits normally.
- **"Only on this computer" clears right after sign-in** (#269): adopting or creating the home repository in Hestia now records GitHub's definite answer that it is private, so `lifestream backup-state` stops saying `local_only` at once instead of at the watcher's next run. The engine is now the one writer of `private-check.json`: the watcher hands its answer to the new `lifestream home record-private OWNER/NAME true|false` instead of writing the file itself. A public or gone repository is recorded as not private; an offline, signed-out or unclear answer (a redirect, a reply without a yes/no) records nothing, where the watcher used to record a redirect as "not private".
- **Capture coverage** (#173): the capture list now survives an OS upgrade (a new version folder starts from the nearest other version's list). Symlinked
  dotfiles (a stow layout) are captured by their target's content, never as a link, when the target is inside your home folder and
  allowed by the never-capture list; others are listed in `SKIPPED.txt`. A cloned folder such as `~/.config/nvim` is stored as its files, without
  its `.git`. Third-party apt sources in the newer `.sources` format are captured and restored like `.list` files.
- **The machine watcher no longer fails quietly** (#166-#172). A failed commit, push or capture is a `watch.json` result that starts
  `FAILED` with the first line of the reason, and the unit exits 1; offline, signed out, repository gone and repository public are told
  apart. A push rejected because another computer pushed first is fetched and rebased. Files over 50 MB and unreadable files are
  skipped and listed in `SKIPPED.txt`. A possible secret in an unsent commit is redone from what GitHub has. File names with spaces,
  accents, apostrophes, `#` or a newline are handled. A refused mass deletion can be confirmed (`touch .accept-smaller-capture`) and a
  changed capture list resets the check. A stale `index.lock` is cleared, a hung push times out (`TimeoutStartSec`, fetch/push
  timeouts), a second run reports it was refused (exit 75), and waiting for a quiet computer ends after 6 hours.
  The engine's `secret-scan` streams files, takes folders, prints `-z` NUL-separated results and exits 2 when it could not look.

### Security
- Secret scanner and deny-list, red-team round 3 (#175): JSON-quoted keys, bare `PASSWORD=`/`DB_PASS=`/`MYSQL_PWD=` values, `--password=`, libpq and rclone
  lines, `curl -u`, Slack, Stripe, SendGrid, JWT, Authorization headers, Azure, WireGuard and kubernetes keys, base64-wrapped private keys. The push
  scan no longer skips added lines starting `++` or merge commits. The deny-list now covers credential files, browser, chat and password-manager
  profiles, shell histories, VPN files and `id_dsa`, and refuses a parent folder (`~/.config`, `~/.docker`) that holds any of them.
- **Restore hardened against a poisoned home repository** (#174): file by file with a `.bak` of anything different (no more skipping whole existing folders), a fixed list of names, never `~/.ssh`, `~/.gnupg` or the keyring, shell startup files, `.gitconfig`, `environment.d`, fish/zsh/bash config held back until `--allow-executable`, file modes restored, honest counts in the summary.
- One shared secret scanner (modern token formats, short quoted or exported passwords, binaries) gates capture, push and
  publish; secret lines are left out of the backup, private keys drop the file.
- Pushes go only to a private GitHub repository of yours, checked on the address git will really use.
- One list of paths that are never captured, read by capture, the Machine screen and the starter manifest.
- File names reach the local model only as cleaned data; the model cannot choose a destination.
- Capture can no longer delete a live file; the mover refuses symlinks, overwrites and hidden destinations.
- Clipboard history is off by default, filters codes and secrets, is readable only by you and deleted when turned off.
- The never-capture list also applies to files inside captured folders (for example a file-manager bookmarks file).
- Desktop settings are captured by allowlist; the launcher ignores toggles while the screen is locked.
- CI actions are pinned to commits; the release workflow reads by default and only its job can write.
- See `docs/THREAT_MODEL.md` for every finding, its status and the release gate.

### Changed
- **One home-repository setting**: the `home=` line in `~/.config/hestia/settings` is the only place that says where your home
  repository is. The app, the watcher, the nightly scan and the restore script all read it; `install.sh` only seeds it. The path
  baked into the systemd units and the `environment.d` file are gone.
- "Answer similar folders together" is off until you choose it.
- Auto-push is on by default (`HESTIA_AUTOPUSH=0` turns it off).

### Known limits
- `lifestream update` cannot update a downloaded release yet (it says so); install the new tarball, which keeps the previous build for `lifestream update rollback`. A rollback does not put back the desktop entry, icons or extension of the older build.
- No release has been cut, so signing and attestation are unexercised.
- The `.deb` needs `hestia-setup` run once per person to turn on the background backup (a package can only place files under /usr).
- Not yet tried on a clean OS image with a real desktop session (`docs/VISION_FIT.md`).
